# Resumen de Contexto para Agente

### 1. Estado Actual
El sistema **Exocortex RSA** gestiona la memoria persistente para el trabajo asistido por IA en la Red Sísmica del Austro. Actualmente cuenta con un único usuario activo y está distribuido en tres niveles de repositorios:
* **Toolkit:** `RSA-Agent-Toolkit` (skills y reglas del agente).
* **Memoria Episódica:** `RSA-Bitacora-LLM-[Usuario]` (diario de trabajo personal).
* **Memoria Semántica:** `RSA-Metodologias` (conocimiento institucional).

Las bitácoras episódicas personales funcionan bien para reanudar sesiones y generar los informes de actividades mensuales para respaldo administrativo.

---

### 2. Problemática Identificada
1. **Fricción operativa:** El sistema requiere múltiples pasos explícitos (`sincronizar_toolkit`, `volcado_bitacora`, etc.), lo que provoca olvidos frecuentes bajo presión de tiempo.
2. **Contaminación de información:** La bitácora episódica es "sucia" por naturaleza (registra logs, comandos, pruebas fallidas y conversaciones informales). Mezclar ese ruido con la documentación arquitectónica dificulta usar el sistema como fuente confiable.
3. **Falta de una Fuente de Verdad Unificada:** No existe una separación clara entre el trabajo exploratorio/temporal y las decisiones técnicas confirmadas que deben prevalecer en la RSA.
4. **Barrera de adopción:** La complejidad de gestionar tres repositorios de forma manual dificulta que otros miembros del equipo con menor dominio de IA adopten la metodología.

---

### 3. Solución Propuesta
1. **Desacoplamiento Estricto de Memorias:**
   * **Memoria Episódica (Bitácoras):** Se mantiene como un registro privado, sucio e incremental para trabajo diario e informes administrativos.
   * **Memoria Semántica (`RSA-Metodologias`):** Se consolida como la **Fuente Única de Verdad (SST)**, inmutable y limpia, disponible para consulta de desarrolladores e IAs.
2. **Estructura Modular en `RSA-Metodologias` por Proyecto:**
   * `SYSTEM_STATE.md`: Snapshot ligero (<300 líneas) con el estado estable y activo del proyecto. Es el primer archivo que lee cualquier agente.
   * `/adr/`: Registro formal e inmutable de Decisiones de Arquitectura.
   * `changelog-curado.md`: Registro de hitos y cambios que llegaron a producción o ramas principales.
3. **Protocolo de Promoción:** Proceso controlado (vía comandos o prompts del agente) para extraer únicamente las decisiones confirmadas desde la bitácora hacia la memoria semántica.
4. **Automatización:** Creación de un punto de entrada único (script CLI / Git Hooks) para automatizar los comandos de inicio, sincronización y cierre de sesión.
