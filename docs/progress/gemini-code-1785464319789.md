# TRANSICIÓN TÉCNICA: Rediseño de Memoria Semántica (RSA-Metodologias)

**Proyecto:** Exocortex RSA — Sistema de Memoria Asistida por IA  
**Fecha:** 30 de julio de 2026  
**Estado:** Definición de Arquitectura / Fase de Estructuración  
**Objetivo:** Establecer `RSA-Metodologias` como la Fuente Única de Verdad (Single Source of Truth - SST) inmutable y limpia, desacoplándola de la memoria episódica (bitácoras personales).

---

## 1. Resumen de Contexto y Acuerdos Consolidados

1. **Separación de Funciones de Memoria:**
   - **Memoria Episódica (`RSA-Bitacora-LLM-[Usuario]`):** Registro incremental, personal y "sucio" (comandos, errores, pruebas fallidas, contextos temporales). Su fin principal es servir como respaldo para la reanudación inmediata de tareas y la generación de **informes de actividades mensuales**.
   - **Memoria Semántica (`RSA-Metodologias`):** Fuente Única de Verdad (SST) para la institución. Almacena solo el estado estable del código, especificaciones técnicas y decisiones confirmadas.

2. **Criterio de Promoción de Datos:**
   - Nada pasa directamente del chat o bitácora a `RSA-Metodologias` sin un filtro o confirmación explícita.
   - Las decisiones confirmadas, cambios de arquitectura y nuevos hitos se promueven desde la bitácora episódica mediante comandos/prompts de extracción específicos.

3. **Restricciones Activas:**
   - Actualmente hay un único usuario activo del sistema, por lo que la estructura debe simplificarse al máximo para reducir la carga cognitiva manual antes de intentar la adopción por parte de otros miembros del equipo.

---

## 2. Propuesta Formal: Estructura de Directorios (`RSA-Metodologias`)

Esta estructura organiza el conocimiento global de la RSA y separa la memoria viva de cada proyecto individual para optimizar las lecturas por parte de desarrolladores e IAs:

```text
RSA-Metodologias/
├── global/                            # Guías y estándares institucionales generales
│   ├── git/                           # Flujos de ramas, formato de commits
│   ├── entornos/                      # Configuración de WSL, Micromamba, Docker
│   └── exocortex/                     # Manuales de uso del sistema Exocortex
│
└── proyectos/                         # Memoria Semántica por Proyecto
    ├── <nombre-proyecto-1>/
    │   ├── README.md                  # Propósito, repositorio remoto y vista general
    │   ├── SYSTEM_STATE.md            # [CRÍTICO] Snapshot inmutable del estado actual
    │   ├── arquitectura/              # Diagramas y descripción de componentes
    │   │   ├── componentes.md
    │   │   └── flujos-datos.md
    │   ├── adr/                       # Registro Inmutable de Decisiones de Arquitectura
    │   │   ├── 0000-template.md
    │   │   ├── 0001-protocolo-comunicacion.md
    │   │   └── 0002-seleccion-base-datos.md
    │   └── changelog-curado.md        # Historial de cambios confirmados (Hitos)
    │
    └── <nombre-proyecto-2>/
        └── ...
```

## 3. Especificación de Componentes Clave

### A. `SYSTEM_STATE.md`
- **Rol:** Es la puerta de entrada para cualquier agente de IA. Resume en un solo lugar el estado **actual y estable** del sistema sin incluir historial acumulado.
- **Regla de Tamaño:** Mantenido bajo las 200–300 líneas para optimizar la ventana de contexto del LLM.
- **Contenido:**
  - Versión actual y ramas activas.
  - Puertos, variables de entorno clave y servicios en ejecución.
  - Dependencias críticas y versiones de runtime (ej. Python 3.11, Docker, C++).
  - Bugs conocidos o bloqueos activos.

### B. Módulo ADR (`/adr/`)
- **Rol:** Almacenar las Decisiones de Arquitectura de forma cronológica e inmutable.
- **Estados válidos:** `[Propuesto | Aceptado | Reemplazado por ADR-XXXX]`.
- **Regla:** Un ADR aceptado jamás se modifica retroactivamente. Si las circunstancias cambian, se redacta un nuevo ADR que reemplaza formalmente al anterior.

### C. Protocolo de Promoción (Filtro de Información)

| Contenido en Bitácora Personal | Tratamiento | Destino en `RSA-Metodologias` |
| :--- | :--- | :--- |
| Logs, errores de sintaxis, pruebas fallidas | Permanece en bitácora local/personal. | **Ninguno** (solo para informe mensual). |
| Nuevas dependencias, cambio de estructura o API | Promoción requerida. | Actualización de `SYSTEM_STATE.md`. |
| Selección entre alternativas técnicas o decisiones | Promoción requerida. | Nuevo archivo en `/adr/`. |
| Hito completado / Versión funcional | Promoción requerida. | Registro en `changelog-curado.md`. |
